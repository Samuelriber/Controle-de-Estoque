Visão geral

Uma API REST em Java + Spring Boot que cadastra, consulta, altera e exclui mercadorias e o seu estoque, gravando tudo em um banco MySQL.

Duas entidades

Mercadoria: nome e preço.

Estoque: quantidade, mínimo, máximo e localização. Cada estoque pertence a uma mercadoria.

API REST

Quatro verbos HTTP: GET consulta, POST cadastra, PUT altera, DELETE exclui.

As rotas são /mercadorias e /estoques.

Tecnologias

Java 21, Spring Boot 4, Spring Data JPA, MySQL, Bean Validation, Lombok e Swagger.

    Uma mercadoria pode ter vários registros de estoque (por exemplo, em prateleiras diferentes). Cada estoque aponta para uma única mercadoria por id_merc.

    Script SQL

    CREATE TABLE mercadoria (
    id_merc INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco DECIMAL(10,2) NOT NULL
);

CREATE TABLE estoque (
    id_estoque INT AUTO_INCREMENT PRIMARY KEY,
    quantidade INT NOT NULL,
    quant_min INT NOT NULL,
    quant_max INT NOT NULL,
    localizacao VARCHAR(100) NOT NULL,
    id_merc INT NOT NULL,
    FOREIGN KEY (id_merc) REFERENCES mercadoria(id_merc),
    CONSTRAINT chk_quantidade CHECK (quantidade >= 0),
    CONSTRAINT chk_limites CHECK (quant_min >= 0 AND quant_max >= quant_min)
);

    O que explicar

    • Chave primária: AUTO_INCREMENT faz o banco gerar os ids.
    • Chave estrangeira: o banco impede um estoque de apontar para uma mercadoria que não existe.
    • CHECK: o próprio banco recusa quantidade negativa e máximo menor que o mínimo.
    • DECIMAL para o preço: guarda o valor exato, sem erros de arredondamento.

    Model (entidades)

    Classes Java que representam as tabelas. Cada atributo vira uma coluna.

    Mercadoria

    @Entity // representa uma tabela do banco
@Table(name = "mercadoria")
@Getter @Setter @NoArgsConstructor
public class Mercadoria {

    @Id // chave primária
    @GeneratedValue(strategy = GenerationType.IDENTITY) // auto increment
    @Column(name = "id_merc")
    private Integer id;

    @Column(name = "nome", nullable = false, length = 100)
    private String nome;

    @Column(name = "preco", nullable = false, precision = 10, scale = 2)
    private BigDecimal preco;
}

    Estoque (com o relacionamento)

    @Entity
@Table(name = "estoque")
@Getter @Setter @NoArgsConstructor
public class Estoque {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id_estoque")
    private Integer id;

    @Column(name = "quantidade", nullable = false)
    private Integer quantidade;

    @Column(name = "quant_min", nullable = false)
    private Integer quantidadeMinima;

    @Column(name = "quant_max", nullable = false)
    private Integer quantidadeMaxima;

    @Column(name = "localizacao", nullable = false, length = 100)
    private String localizacao;

    @ManyToOne(optional = false) // muitos estoques para uma mercadoria
    @JoinColumn(name = "id_merc", nullable = false) // coluna da chave estrangeira
    private Mercadoria mercadoria;
}

    O que explicar

    • @Entity e @Table: ligam a classe à tabela.
    • @Id e @GeneratedValue: chave primária gerada pelo banco.
    • @ManyToOne e @JoinColumn: criam o relacionamento e a chave estrangeira id_merc.
    • BigDecimal no preço: valor exato, ao contrário de double.
    • Lombok (@Getter, @Setter): gera os getters e setters sem precisar escrevê-los.

    Repository

    A camada de acesso aos dados. São interfaces vazias, e o Spring escreve o código por trás.

    public interface MercadoriaRepository extends JpaRepository<Mercadoria, Integer> {
}

public interface EstoqueRepository extends JpaRepository<Estoque, Integer> {
}

    Os dois tipos entre < > são a entidade e o tipo do id. Com isso, ganhamos sem escrever SQL:

    findAll()lista todos os registros (SELECT *)
    findById(id)busca um registro pelo id
    save(obj)insere ou atualiza (INSERT ou UPDATE)
    deleteById(id)exclui um registro (DELETE)
    existsById(id)diz se o id existe

    DTO

    DTO (Data Transfer Object) é o formato do JSON que entra e sai da API. A entidade não é exposta diretamente.

    Request: o que o cliente envia

    public record MercadoriaRequest(

  @NotBlank(message = "O nome é obrigatório")
  @Size(max = 100, message = "...")
  String nome,

  @NotNull(message = "O preço é obrigatório")
  @PositiveOrZero(message = "O preço não pode ser negativo")
  BigDecimal preco
) {}

    Response: o que a API devolve

    public record EstoqueResponse(
  Integer id,
  Integer quantidade,
  Integer quantidadeMinima,
  Integer quantidadeMaxima,
  String localizacao,
  Integer idMerc,
  String nomeMercadoria
) {}

    O que explicar

    • O Request carrega as validações (@NotBlank, @NotNull, @PositiveOrZero...) com mensagens em português.
    • No cadastro de estoque, o cliente envia só o idMerc. Na resposta, a API devolve também o nomeMercadoria, para facilitar a tela.
    • O DTO não traz o id na entrada: o id é sempre gerado pelo banco.
    • São record do Java: classes imutáveis e curtas, ideais para transportar dados.

    Service

    Aqui ficam as regras de negócio. O controller pergunta, o service decide.

    A regra do estoque

    private void preencher(Estoque estoque, EstoqueRequest request) {

    // regra 1: máximo não pode ser menor que o mínimo
    if (request.quantidadeMaxima() < request.quantidadeMinima()) {
        throw new RegraNegocioException(
            "A quantidade máxima não pode ser menor que a quantidade mínima");
    }

    // regra 2: a mercadoria precisa existir
    Mercadoria mercadoria = mercadoriaRepository.findById(request.idMerc())
        .orElseThrow(() -> new RecursoNaoEncontradoException(
            "Mercadoria não encontrada: id " + request.idMerc()));

    estoque.setQuantidade(request.quantidade());
    estoque.setQuantidadeMinima(request.quantidadeMinima());
    estoque.setQuantidadeMaxima(request.quantidadeMaxima());
    estoque.setLocalizacao(request.localizacao().trim());
    estoque.setMercadoria(mercadoria);
}

    Os métodos do service

    listar()busca tudo e converte cada item em Response
    buscar(id)busca um; se não existir, lança erro 404
    criar(request)cria uma entidade nova, preenche e salva
    atualizar(id, request)busca a existente, preenche de novo e salva
    excluir(id)confere se existe e exclui

    O que explicar

    • @Service marca a classe como camada de regras de negócio.
    • @Transactional: a operação acontece por inteiro ou não acontece. Se der erro no meio, o banco volta ao que era.
    • @Transactional(readOnly = true) nas consultas, que só leem.
    • Criar e atualizar usam o mesmo método preencher, então as regras valem para os dois.
    • trim() remove espaços sobrando no começo e no fim dos textos.

    Controller

    A porta de entrada da API. Recebe a requisição HTTP, valida e chama o service.

    @Tag(name = "Mercadorias", description = "Cadastro e consulta de mercadorias")
@RestController
@RequestMapping("/mercadorias")
@RequiredArgsConstructor
public class MercadoriaController {

    private final MercadoriaService service;

    @GetMapping
    public List<MercadoriaResponse> listar() {
        return service.listar();
    }

    @GetMapping("/{id}")
    public MercadoriaResponse buscar(@PathVariable Integer id) {
        return service.buscar(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public MercadoriaResponse criar(@Valid @RequestBody MercadoriaRequest request) {
        return service.criar(request);
    }

    @PutMapping("/{id}")
    public MercadoriaResponse atualizar(@PathVariable Integer id,
                                        @Valid @RequestBody MercadoriaRequest request) {
        return service.atualizar(id, request);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void excluir(@PathVariable Integer id) {
        service.excluir(id);
    }
}

    Cada anotação

    @RestControllera classe responde HTTP e devolve JSON
    @RequestMapping("/mercadorias")prefixo da URL de todos os métodos
    @GetMappingconsulta (GET)
    @PostMappingcadastro (POST), responde 201 Created
    @PutMapping("/{id}")alteração (PUT)
    @DeleteMapping("/{id}")exclusão (DELETE), responde 204 No Content
    @PathVariablelê o id que vem na URL
    @RequestBodylê o JSON enviado no corpo
    @Validvalida o JSON antes de entrar no método
    @RequiredArgsConstructorLombok cria o construtor que recebe o service

    O que explicar

    • O controller não tem regra de negócio: só recebe, valida e repassa ao service.
    • Os códigos HTTP são escolhidos de propósito: 201 ao criar e 204 ao excluir.
    • O EstoqueController é igual, com a rota /estoques.

    Tratamento de erros

    Todo erro passa pelo GlobalExceptionHandler, que devolve sempre um JSON padronizado, com uma mensagem clara.

    404

    Não encontrado

    RecursoNaoEncontradoException

    O id pedido não existe.

    400

    Regra de negócio

    RegraNegocioException

    Máximo menor que o mínimo.

    400

    Dados inválidos

    MethodArgumentNotValidException

    O JSON falhou nas validações.

    409

    Conflito

    DataIntegrityViolationException

    Excluir mercadoria que tem estoque.

    O handler

    @RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(RecursoNaoEncontradoException.class)
    public ResponseEntity<ErroResponse> naoEncontrado(RecursoNaoEncontradoException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
                .body(ErroResponse.de(404, ex.getMessage()));
    }

    @ExceptionHandler(DataIntegrityViolationException.class)
    public ResponseEntity<ErroResponse> integridade(DataIntegrityViolationException ex) {
        return ResponseEntity.status(HttpStatus.CONFLICT)
                .body(ErroResponse.de(409,
                    "Operação não permitida: o registro está relacionado a outros dados"));
    }
    // ... e os handlers de 400
}

    O formato do erro

    {
  "status": 400,
  "mensagem": "Dados inválidos",
  "campos": {
    "nome": "O nome é obrigatório",
    "preco": "O preço não pode ser negativo"
  }
}

    O que explicar

    • @RestControllerAdvice faz uma classe ouvir os erros de todos os controllers.
    • Sem isso, o Spring mostraria uma página de erro feia. Com isso, o frontend recebe um JSON com a mensagem, pronto para exibir ao usuário.
    • Nos erros de validação, campos diz exatamente qual campo falhou e por quê.

    Swagger

    Uma página gerada automaticamente que documenta a API e permite testá-la no navegador.

    Com o backend rodando, abra:

    http://localhost:8080/swagger-ui/index.html

    Como foi feito

    1. Dependência springdoc-openapi-starter-webmvc-ui no pom.xml.
    2. Uma classe de configuração com o título e a descrição: 
      @Configuration
public class OpenApiConfig {

    @Bean
    public OpenAPI apiInfo() {
        return new OpenAPI().info(new Info()
                .title("API de Controle de Estoque")
                .description("API REST para cadastro e controle de mercadorias e estoques.")
                .version("1.0"));
    }
}
    3. @Tag em cada controller, para nomear os grupos Mercadorias e Estoques.

    Como usar na demonstração

    1. Abra POST /mercadorias e clique em Try it out.
    2. Preencha o JSON, clique em Execute e veja o 201.
    3. Cadastre um estoque em POST /estoques usando o idMerc criado.
    4. Teste os erros: um preço negativo, um idMerc que não existe e a exclusão de uma mercadoria com estoque.

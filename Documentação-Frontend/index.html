Visão geral

O que é o frontend deste projeto

O frontend é a parte do sistema que roda no navegador: as telas, os botões, as tabelas e os formulários. Ele não guarda dados. Toda informação vem do backend (Spring Boot + MySQL), e o frontend só pede, mostra e envia.

📦 Mercadorias

Lista, cadastra, edita e exclui produtos (nome e preço).

🏷️ Estoques

Liga uma mercadoria a um local, com quantidade atual, mínima e máxima.

🏠 Início

Resumo: quantos registros existem e quantos estoques estão abaixo do mínimo.

🚫 Página não encontrada

Aparece quando o endereço não corresponde a nenhuma tela.

É uma SPA (Single Page Application, aplicação de página única): o navegador carrega um único index.html e, a partir daí, o JavaScript troca o conteúdo da tela sem recarregar a página. Quando você clica em "Mercadorias", nada é baixado de novo; o React só desenha outra tela.

O caminho de um clique, resumido

Você clica num botão
   └─► a página (pasta pages/) reage ao clique
         └─► chama uma função da API (pasta api/)
               └─► http.js faz o fetch para o backend
                     └─► o backend responde com JSON
         ◄─── a página guarda a resposta no estado (useState)
   ◄── o React redesenha a tela com os dados novos
Este documento tem três partes: (1) o básico para se localizar, (2) animações interativas mostrando cada mecanismo funcionando e (3) todo o código-fonte, arquivo por arquivo, com explicações. Clique numa explicação para destacar as linhas correspondentes no código.

Pré-requisito

React em 5 minutos

Se você nunca viu React, estes são os únicos conceitos usados no projeto.

Componente

Um componente é uma função JavaScript que devolve o que deve aparecer na tela. O nome começa com letra maiúscula.

function Carregando({ texto }) {
  return <p className="carregando">{texto}</p>;
}

// Usando:  <Carregando texto="Carregando mercadorias..." />

JSX

O "HTML dentro do JavaScript" acima chama-se JSX. Diferenças que aparecem no projeto: usa-se className no lugar de class, htmlFor no lugar de for, e qualquer coisa entre { } é JavaScript. Para mostrar algo só às vezes usa-se {condicao && <Algo />}; para listas, {lista.map(item => <tr key={item.id}>...)}.

Props

São os "parâmetros" de um componente, passados como atributos: em <Carregando texto="..." />, texto é uma prop. A prop especial children é o que vai entre a tag de abertura e a de fechamento.

Estado: useState

Variáveis normais são esquecidas a cada redesenho. O estado é uma memória do componente: quando muda, o React redesenha a tela sozinho.

const [enviando, setEnviando] = useState(false);  // começa false
setEnviando(true);   // o React redesenha e o botão vira "Salvando..."

Efeito: useEffect

Código que roda depois que a tela é desenhada, por exemplo buscar dados ou mudar o título da aba. A lista no final ([titulo]) diz quando rodar de novo: só quando algum desses valores mudar. A função que o efeito devolve é a "limpeza", rodada antes da próxima execução ou quando o componente sai da tela.

Referência: useRef

Uma caixa que guarda um valor sem provocar redesenho. No projeto serve para apontar para elementos reais da página (o <form>, o <dialog>, o <h1>) e poder chamar .focus() ou .showModal() neles.

Hook

Toda função que começa com use é um hook. Os do React são useState, useEffect, useRef e useCallback. Os do React Router são useParams, useNavigate, useLocation e useSearchParams. O projeto cria os seus em src/lib/hooks.js: useTitulo, useCarregar e useAviso.

async / await e Promise

Pedir algo ao servidor demora. Uma Promise é "um valor que vai chegar depois". Dentro de uma função async, await espera esse valor. Se der erro, ele cai no catch.

try {
  const salva = await criarMercadoria(corpo);  // espera o servidor
} catch (erro) {
  // servidor recusou ou está fora do ar
}

Passo a passo

  1. Suba o backend (Spring Boot) em http://localhost:8080, com o MySQL ligado.
  2. Entre na pasta frontend e instale as dependências: npm install (cria a pasta node_modules).
  3. Rode npm run dev. O Vite abre o servidor em http://localhost:5173.
  4. Abra esse endereço no navegador. Pronto.
cd frontend
npm install
npm run dev        # desenvolvimento: http://localhost:5173
npm run build      # gera a versão final na pasta dist/
npm run preview    # serve a pasta dist/ para conferir o build
Por que o front não precisa saber o endereço do backend em desenvolvimento? Porque o Vite funciona como intermediário (proxy): o navegador pede /mercadorias ao próprio Vite (porta 5173), e o Vite repassa para localhost:8080. Em produção, você informa o endereço real em VITE_API_URL num arquivo .env. Veja a animação em Conversa com o backend.

A regra de organização

pages/

Uma tela inteira por arquivo. Cada uma corresponde a uma rota.

components/

Pedaços reaproveitados por várias telas (campo, alerta, diálogo...).

api/

Única parte que fala com o backend. As telas nunca chamam fetch direto.

lib/

Funções auxiliares sem tela: hooks, validação, formatação, regra de situação.

styles/

O CSS: variáveis (tokens), base e componentes.

Quem importa quem

main.jsx ──► App.jsx ──► components/Layout.jsx
                    └──► pages/*.jsx ──► components/*.jsx
                                     ├──► api/mercadorias.js ─┐
                                     ├──► api/estoques.js ────┴──► api/http.js ──► fetch()
                                     └──► lib/hooks.js, validar.js, formatar.js, situacao.js

As setas sempre apontam "para baixo": páginas usam componentes e funções, mas componentes nunca importam páginas, e api/ não sabe nada de telas. Isso deixa cada parte fácil de entender isoladamente.

Para que serve a variável ativo? Se você sai da tela antes do servidor responder, a resposta ainda chega. Sem o ativo, o hook tentaria atualizar uma tela que não existe mais (ou, pior, mostrar dados velhos numa tela nova). A função de limpeza do useEffect põe ativo = false, e a resposta atrasada é ignorada. Teste com o botão "Sair da tela antes da resposta".

Na prática

  
Como criar uma tela nova

  
Exemplo: uma tela "Fornecedores" que lista dados de GET /fornecedores.

  
    
    
  1. API: crie src/api/fornecedores.js copiando mercadorias.js e trocando o caminho.
    2. 
    
  2. Página: crie src/pages/FornecedoresLista.jsx seguindo o roteiro das outras listas.
    3. 
    
  3. Rota: em App.jsx, importe a página e adicione <Route path="fornecedores" element={<FornecedoresLista />} /> dentro da rota do Layout.
    4. 
    
  4. Menu: em Layout.jsx, adicione um <li><NavLink to="/fornecedores">Fornecedores</NavLink></li>.
    5. 
    
  5. Proxy: em vite.config.js, adicione '/fornecedores': rotaApi. Sem isso, em desenvolvimento a chamada não chega ao backend.
    6. 
  

  
import { listarFornecedores } from '../api/fornecedores.js';
import Carregando from '../components/Carregando.jsx';
import EstadoErro from '../components/EstadoErro.jsx';
import { useCarregar, useTitulo } from '../lib/hooks.js';

export default function FornecedoresLista() {
  useTitulo('Fornecedores');
  const lista = useCarregar(listarFornecedores);

  let conteudo;
  if (lista.status === 'carregando') conteudo = <Carregando texto="Carregando fornecedores..." />;
  else if (lista.status === 'erro') conteudo = <EstadoErro erro={lista.erro} onTentar={lista.recarregar} />;
  else conteudo = (
    <ul>{lista.dados.map((f) => <li key={f.id}>{f.nome}</li>)}</ul>
  );

  return (
    <>
      <div className="cabecalho-pagina"><h1 tabIndex={-1}>Fornecedores</h1></div>
      {conteudo}
    </>
  );
}






  
Consulta rápida

  
Glossário

  

    
API / endpoint
Endereço do backend que recebe pedidos, como GET /mercadorias.

    
CORS
Regra de segurança dos navegadores: um site só pode chamar outro endereço se esse outro permitir. O proxy do Vite evita o problema em desenvolvimento.

    
CRUD
Create, Read, Update, Delete: cadastrar, consultar, alterar e excluir.

    
DOM
A estrutura da página na memória do navegador. O React altera o DOM por você.

    
Fragment (<>...</>)
Agrupa elementos sem criar uma tag a mais.

    
HTTP 200 / 201 / 204
Sucesso / criado / sucesso sem conteúdo.

    
HTTP 400 / 404 / 409 / 500 / 502
Dados inválidos / não encontrado / conflito com regra / erro interno / intermediário não conseguiu falar com o servidor.

    
JSON
Formato de texto para trocar dados: { "nome": "Arroz", "preco": 25.9 }.

    
Proxy
Intermediário que recebe uma chamada e repassa para outro endereço.

    
Redesenho (render)
Quando o React executa a função do componente de novo e atualiza a tela. Acontece quando estado ou props mudam.

    
Rota
Associação entre um endereço e uma tela.

    
SPA
Aplicação de página única: troca de tela sem recarregar.

    
Leitor de tela
Programa que lê a página em voz alta (NVDA, VoiceOver, Orca).
